# ADR-0019: Desktop packaging: per-user installers, a signed updater, development signing and crash reports

- **Status:** Accepted
- **Date:** 2026-10-11
- **Sub-project:** SP-08c (desktop), with SP-07c's release registry (ADR-0021)

## Context

- **PRD §26–§28** put an update gate in front of sign-in; the master plan (§3.2(11), §6.4, §13) adds:
  - installs are per-user, for x64 and ARM64, with no admin rights;
  - WebView2 Evergreen;
  - a signed updater, development code signing, and GlitchTip crash reports.
- **SP-08's exit criteria:**
  - an update is signature-verified and a downgrade is refused;
  - the app installs without admin rights;
  - a tauri-driver test goes from sign-in to "Ready".
- **The server already** keeps the release registry and answers `GET /desktop/update-manifest/{target}/{arch}/{current_version}` in Tauri's format (contract `candidate-auth.md`).
- **ADR-0018's rule** still holds: the webview never calls the API and the CSP's `connect-src` has no API origin.

## Decision

- **Installers:**
  - **Format:** the Tauri bundler's NSIS target, one installer per architecture, `installMode: currentUser` (no elevation), English only.
  - **WebView2:** the download bootstrapper, silent. Windows 11 and current Windows 10 already have the runtime.
  - **Build:** `pnpm --filter @hirevion/ai-interviewer-desktop bundle [-- --target x64|arm64|all]`.
  - **No licence page:** there is no approved text to show yet.
- **The updater is driven from Rust, not the webview:**
  - **Command:** the update-required screen calls `update_install`, which checks the manifest, downloads with progress, verifies, and installs.
  - **Permissions:** no `updater:*` or `process:*` permission is granted, so a compromised webview can't aim the updater anywhere. The endpoint is the compiled-in API root.
  - **No process plugin:** NSIS updates run the installer with `/R`, which starts the new version itself, so `tauri-plugin-process` has nothing to add.
  - **Proof:** the manifest request carries a DPoP proof, so the server can place the device in a staged rollout. The bundle download carries no headers.
- **Three guards on every update:**
  1. HTTPS only. Release builds refuse `http`.
  2. A minisign signature, verified against the public key in `tauri.conf.json`.
  3. Strictly newer only. `is_upgrade` is the app's comparator, and `requireSignedVersion` makes the plugin check that the signature was made for the version the manifest announces, so a genuine old bundle can't be passed off as a new one. `tests/updater.rs` drives the real plugin against a fake server and checks that a lower or equal version is refused.
- **Keys:**
  - **Development updater key:** made with `tauri signer generate`, kept outside the repo at `%USERPROFILE%\.hirevion\updater-dev.key`. Its password is `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in the gitignored root `.env`. Only the public key is committed.
  - **Production updater key:** a different key, generated by the owner and held in a secrets store. Changing the public key in the app takes a release signed by the old key.
- **Authenticode signing happens inside the bundler** (`certificateThumbprint`), before the updater signature is made, so the minisign signature covers the exact file that ships.
  - **Development:** a self-signed certificate is created on demand in `CurrentUser\My` and never exported. It proves the step works; Windows doesn't trust it.
  - **Skipping it:** `HV_SIGN=0`.
  - **Production:** the OV certificate replaces it later through `HV_SIGN_THUMBPRINT` and `HV_SIGN_TIMESTAMP_URL`.
- **Crash reports** go to GlitchTip (Sentry-compatible), only when `HV_GLITCHTIP_DSN` was set at build time.
  - **Rust side:** the `sentry` crate (MIT) with `backtrace`, `contexts`, `panic` and `reqwest` over rustls (ring) only. No default features, so no debug images, logs, metrics or session tracking.
  - **Webview side:** errors go to Rust through the `crash_report` command. There's no `@sentry/browser` and no CSP change.
  - **Scrubbing:** every event passes one scrubber first (`crash.rs`). It drops the user, request, computer name, source lines and variables, and redacts emails, tokens, profile paths and addresses.
  - **Cap:** 25 webview reports per run.
  - **No minidumps:** `sentry-rust-minidump` hasn't been checked against the licence policy.
- **End-to-end test:** `pnpm --filter @hirevion/ai-interviewer-desktop e2e` runs the debug build on its stub backend.
  - **Tools:** `tauri-driver` 2.1 and the `msedgedriver` that matches the installed WebView2, downloaded once.
  - **Client:** a 100-line W3C WebDriver client over `fetch`, instead of WebdriverIO's few hundred packages.
  - **Determinism:** fake camera and microphone, and canned native checks (`HV_DESKTOP_STUB_NATIVE=1`), so it runs the same on a CI runner.
  - **CI:** the `desktop-e2e` job runs when the `desktop` path filter matches.

## Consequences

- **A bad update can't be forced on a device:** the signature, the signed version and the HTTPS check all have to hold, and each is separately tested or inherited from a tested plugin.
- **Updating needs the API** (the manifest comes from it), and a staged rollout only reaches devices that send a proof. A device that can't reach the API keeps its version until it can.
- **Cost:** two signing steps at release time (Authenticode, then minisign) and one more secret to keep (the updater key). Losing the production updater key means shipping a new installer by hand to everyone.
- **Not covered yet:**
  - native crashes outside Rust's panic path;
  - an ARM64 installer built in CI (the script supports it and needs the Visual Studio ARM64 build tools);
  - the production Authenticode certificate.
