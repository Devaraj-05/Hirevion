# SP-03 Web Shell and Design System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the recruitment platform's frame, as specified in `docs/superpowers/specs/2026-09-29-sp-03-web-shell-design.md`:
- the `packages/ui` design system (calm professional, light and dark);
- one Next.js 16 app serving the recruiter host and the candidate-portal host;
- the application shell with every PRD §7 section;
- permission-guarded route skeletons;
- the data-table and form frameworks, and the dashboard layout;
- language and accessibility baselines enforced in CI.

**Architecture:**

- **Hosts.** `recruitment-platform/` is a Next 16 App Router app. `src/proxy.ts`:
  - maps the recruiter host onto `app/recruiter/*` and the portal host onto `app/portal/*` with rewrites, so each host sees only its own routes;
  - sets a nonce-based Content-Security-Policy and the other security headers;
  - refuses a guarded route with a real HTTP 403 when the session lacks its permission.
- **Guards.** A typed route manifest is the single list of routes, their permissions and their navigation entries. Layouts re-check it, so the proxy is never the only guard.
- **Components.** `packages/ui` holds the tokens (CSS custom properties exposed to Tailwind v4) and our own Radix-based components. The app imports them from source.

**Tech Stack:** pinned exactly, as elsewhere in the repo:
- Next 16.3.7, React 19.3.0, TypeScript 7.0.2, Tailwind CSS 4.3.3;
- next-intl 4.14.8;
- Radix (`radix-ui` 1.6.7), class-variance-authority 0.7.1, tailwind-merge 3.7.0, clsx 2.1.1, lucide-react 1.48.0, Sonner 2.0.8, cmdk 1.1.1;
- react-hook-form 7.89.0, zod 4.6.5, @hookform/resolvers 5.9.1;
- TanStack Query 5.104.0 and Table 9.2.4 (v9 API: `useTable`, `tableFeatures`, `table.FlexRender`);
- `@fontsource-variable/inter` 5.3.0;
- Vitest 5.0.2 with Testing Library and jsdom; Playwright 1.63.0 with `@axe-core/playwright` 4.13.0.

## Global Constraints

- Everything in `MASTER_IMPLEMENTATION_PLAN.md` §13 applies. For the UX:
  - every string externalised (en-IN and en-US first);
  - WCAG 2.2 AA;
  - p95 UI interactions under 200 ms;
  - TypeScript strict.
- Biome lints and formats every file, including `style/noJsxLiterals` for app and UI source. Tests and the gallery's sample data may use literals.
- No secret or API key reaches the browser bundle. The web app calls `/api/*` on its own origin; there is no CORS.
- Development sessions (`HV_WEB_DEV_TOOLS=true`) can never run with `HV_ENVIRONMENT=production`: `next.config.ts` throws at build or start if both are set.
- Authorisation is always re-checked where data is read or changed (layouts now; server actions and the API later).

### Task 1: The app, host split, security headers and languages

**Interfaces:**

- Produces:
  - `hostKind(host: string | null, config): "recruiter" | "portal" | "unknown"` (the port is ignored);
  - `internalPath(kind, pathname): string` (`/jobs` → `/recruiter/jobs`; `/status` → `/portal/status`);
  - `buildCsp(nonce: string, dev: boolean): string`;
  - `LOCALES = ["en-IN", "en-US"] as const` and `DEFAULT_LOCALE = "en-IN"`, with the locale cookie `hv_locale`;
  - `pnpm --filter @hirevion/recruitment-platform dev` serves `127.0.0.1:3000`.

- [ ] Scaffold:
  - `recruitment-platform/` (package `@hirevion/recruitment-platform`) and `packages/ui` (`@hirevion/ui`, empty `index.ts`);
  - Tailwind v4 through `@tailwindcss/postcss`, with Inter from `@fontsource-variable/inter` imported in the root layout;
  - add `recruitment-platform` to `pnpm-workspace.yaml`.
- [ ] Tests first (Vitest):
  - **`hostKind`:**
    - `app.hirevion.localhost:3000` → recruiter;
    - `candidate.hirevion.localhost` → portal;
    - `evil.example` → unknown;
    - a missing Host header → unknown.

    Hosts come from `HV_WEB_RECRUITER_HOSTS` and `HV_WEB_PORTAL_HOSTS`, defaulting to the local names plus `localhost` and `127.0.0.1` for the recruiter side.
  - **`internalPath`:** internal prefixes can't be addressed from outside (`/recruiter/x` on the recruiter host → `/recruiter/recruiter/x`, which 404s), and `/` maps to `/recruiter/dashboard` on the recruiter host and `/portal` on the portal host.
  - **`buildCsp`:**
    - contains `script-src 'self' 'nonce-<n>' 'strict-dynamic'`, `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'` and `form-action 'self'`;
    - `'unsafe-eval'` only when `dev`;
    - `style-src 'self' 'unsafe-inline'`, because Radix positions popovers with inline styles.
  - **Catalogues:** `en-IN.json` and `en-US.json` have the same key set, and no value is empty.
  - **Formatting:** en-IN formats 1234567 as `12,34,567`, and en-US as `1,234,567`.
- [ ] Implement `proxy.ts`:
  - a 16-byte random nonce per request, base64;
  - the CSP on both the request headers (so Next applies the nonce to its own scripts) and the response;
  - also `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, and `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`;
  - an unknown host gets 421 (Misdirected Request);
  - the matcher skips `_next/static`, `_next/image`, `favicon.ico` and `api`.
- [ ] Implement `i18n/request.ts` (next-intl without i18n routing): the locale is read from `hv_locale`, falling back to en-IN, and messages load from `messages/<locale>.json`. `<html lang>` follows the locale.
- [ ] `next.config.ts`:
  - throws when `HV_WEB_DEV_TOOLS=true` and `HV_ENVIRONMENT=production`;
  - sets `transpilePackages: ["@hirevion/ui", "@hirevion/api-client"]` and `poweredByHeader: false`.
- [ ] Commit `feat(web): add the recruitment platform app with host split, CSP and languages`.

### Task 2: The design system (`packages/ui`)

**Interfaces:**

- Produces:
  - `tokens.css`, whose light and dark themes are selected by `data-theme` on `<html>` (default light, `prefers-color-scheme` when "system");
  - `cn(...)`;
  - the components:
    - **basics:** `Button` (variants primary, secondary, ghost, danger; sizes sm, md; `asChild`), `IconButton` (requires `label`), `Input`, `Textarea`, `Select`, `Checkbox`, `RadioGroup`, `Switch`, `Label`;
    - **forms:** `FormField` (a react-hook-form `Controller` wrapper that renders label, control, description and error, with `aria-invalid` and `aria-describedby`), and `Form` (the `FormProvider` and `<form noValidate>`);
    - **overlays and navigation:** `Dialog`, `Sheet`, `DropdownMenu`, `Popover`, `Tooltip`, `Tabs`;
    - **display:** `Badge` (tones neutral, accent, success, warning, danger, info, plus `severity="INFO"|"WARNING"|"CRITICAL"` with a text label), `Card`, `Avatar`, `Skeleton`, `EmptyState` (icon, title, description, action), `Breadcrumbs`, `KpiTile` (label, value or `null` shown as "—", optional hint);
    - **feedback and commands:** `Toaster` and `toast` (Sonner), `CommandPalette` (cmdk inside Dialog);
  - `ThemeScript` (an inline script that applies the stored theme before paint; takes a `nonce`) and `useTheme()`.
- [ ] Tests first (Vitest + Testing Library + user-event):
  - `Button` renders its variants and forwards `ref`;
  - `IconButton` without a label is a type error (`// @ts-expect-error`), and with one has the accessible name;
  - `FormField` wires `aria-describedby` to the error and description, and shows a zod message after submit;
  - `Dialog` traps focus and returns it to the trigger on close;
  - `Tabs` move with the arrow keys;
  - `Badge` `severity="CRITICAL"` has the visible text "Critical" (from a `labels` prop, so the app passes translated text);
  - `KpiTile` with `null` renders "—" and `aria-label` "<label>: no data yet";
  - `useTheme` persists the choice in `localStorage` (`hv_theme`), survives a thrown storage, and sets `data-theme`;
  - `CommandPalette` filters items and calls `onSelect`.
- [ ] Implement the tokens:
  - neutrals `--slate-50` … `--slate-950`, accent `--accent` (indigo-600 light, indigo-400 dark) with `--accent-fg`;
  - semantic `--success`, `--warning`, `--danger`, `--info`, and severity `--sev-info`, `--sev-warning`, `--sev-critical`;
  - `--radius` 0.5rem, `--focus` a 2px accent ring with offset;
  - body 14px/1.5 Inter; `prefers-reduced-motion` turns transitions off.
- [ ] Implement the components. Library components stay string-free: every visible text comes from props.
- [ ] Commit `feat(ui): add the design system tokens and components`.

### Task 3: Sessions, the route manifest and guards

**Interfaces:**

- Produces:
  - `Role = "super_admin" | "org_admin" | "recruiter" | "hiring_manager" | "interviewer"`, and `Permission` (a string union);
  - `Session = { user: { id, name, email }, organization: { id, name } | null, roles: Role[], permissions: Permission[] }`;
  - `ROUTES: RouteEntry[]`, where `RouteEntry = { path, permission, section, titleKey, owner (e.g. "SP-04"), nav?: { icon, order } }`;
  - `routeFor(pathname) -> RouteEntry | undefined` (the longest prefix wins);
  - `can(session, permission) -> boolean`;
  - `getSession(): Promise<Session | null>`: development fixtures from the `hv_dev_role` cookie when `HV_WEB_DEV_TOOLS=true`, otherwise `GET {HV_API_INTERNAL_URL}/api/v1/auth/session` with the incoming cookie (SP-02; any failure is `null`);
  - `requireSession()` (redirects to `/login?next=`) and `requirePermission(permission)` (returns a `<Forbidden/>` element);
  - `DEV_SESSIONS: Record<Role, Session>` and `ROLE_PERMISSIONS: Record<Role, Permission[]>` (provisional until SP-02).
- [ ] Tests first:
  - **Every page has an entry:** every `page.tsx` under `app/recruiter` has a manifest entry, and every entry has a page (the test globs the app directory).
  - **Role matrix:**
    - super admin can open `/platform/*`, and no other role can;
    - org admin can open `/admin/*`;
    - a recruiter can open jobs, candidates, interviews, questions and reports, but not admin;
    - a hiring manager can open dashboard, jobs, candidates, interviews and reports only (view);
    - an interviewer can open dashboard, interviews and interview reports.
  - **Proxy guard:** an anonymous visitor to a guarded path is redirected to `/login?next=/jobs`; a recruiter asking for `/admin/users` gets a rewrite to `/recruiter/forbidden` with status 403; public paths (`/login`, `/forbidden`) are never guarded.
  - **Development tools:** `getSession()` ignores `hv_dev_role` when `HV_WEB_DEV_TOOLS` is unset, and returns `null` when the API is unreachable.
- [ ] Implement:
  - the proxy guard: `routeFor` plus `getSession` on the request's cookies;
  - `app/recruiter/layout.tsx` calls `requireSession()`, and each section layout calls `requirePermission()`;
  - `/login` (the development role picker when tools are on; otherwise a notice that sign-in arrives with SP-02) and `/forbidden`.
- [ ] Commit `feat(web): add the session contract, route manifest and permission guards`.

### Task 5: Route skeletons, data layer, data table and dashboard

**Interfaces:**

- Produces:
  - `PageHeader`, `SectionTabs` (links with `aria-current`) and `Placeholder` (an `EmptyState` naming the owner sub-project from the manifest);
  - `QueryProvider`, `apiClient()` (`createApiClient({ baseUrl: window.location.origin })`) and `useProblemToast()`;
  - `useCursorPage(queryKey, fetchPage)` returning `{ rows, nextPage(), previousPage(), hasNext, hasPrevious }`, keeping a stack of cursors;
  - `DataTable<T>` (in `@hirevion/ui`), built on TanStack v9 `useTable` with `rowSortingFeature`, `rowSelectionFeature` and `columnVisibilityFeature`:
    - sorting is controlled through props (URL-owned in the app);
    - a selection column and a bulk-action bar (`aria-live`) with the selected count;
    - a column-visibility menu;
    - a saved-views menu through `ViewStore` (`localStorage` implementation: `list`, `save`, `remove`, keyed by table id);
  - `useUrlTableState(tableId)`: sort and filters live in the search params.
  - Dashboard pieces:
    - `KpiGrid`;
    - `DashboardFilters`, the seven filters in the URL (`from`, `to`, `recruiter`, `team`, `job`, `department`, `candidateStatus`, `interviewStatus`);
    - `PipelineBoard`, nine columns (§72) as a list of lists with `role="list"`, columns keyboard-reachable, each showing a count and an empty state.
- [ ] Tests first:
  - `useCursorPage` goes forward and back with the right cursors;
  - `DataTable` toggles sorting on a header click (calls `onSortingChange`); selection shows the bulk bar with the count; a hidden column disappears; a saved view restores sort, filters and visible columns; `ViewStore` survives thrown storage;
  - filters round-trip through search params;
  - the pipeline board shows the nine statuses in order, with localised labels.
- [ ] Implement every route skeleton from the manifest:
  - Jobs, Candidates, Interviews, Questions and Reports get their tabs.
  - `/jobs` renders a `DataTable` with an empty data set and its placeholder.
  - Admin and platform pages get placeholders.
  - `/notifications` is a list page with an empty state.
  - Portal pages: `/portal` (status), `/invitation/[token]`, `/set-password`, `/download`, `/notices`, `/report`, `/requests`.
  - A development gallery `/dev/ui` (only when `HV_WEB_DEV_TOOLS=true`; otherwise 404) shows every component in both themes, with demo table data.
- [ ] Commit `feat(web): add the route skeletons, data table and dashboard layout`.

### Task 6: End-to-end checks, CI and docs

- [ ] Playwright:
  - **Setup:** `playwright.config.ts` runs `next build && next start -H 127.0.0.1 -p 3100` with `HV_WEB_DEV_TOOLS=true`. Base URLs are `http://app.hirevion.localhost:3100` and `http://candidate.hirevion.localhost:3100` (Chromium resolves `*.localhost` to loopback).
  - **Routes × roles:** for every manifest route and every role, sign in with the development switcher cookie and visit. A permitted route shows its `h1`; a refused one returns 403 with the Forbidden heading. An anonymous visitor is redirected to `/login`.
  - **axe:** on every route as the super admin, in light and in dark, with the WCAG 2.2 AA tags, expecting no violations.
  - **Keyboard:**
    - Tab first lands on the skip link, and Enter moves focus to `main`;
    - the sidebar is reachable by Tab;
    - Ctrl+K opens the palette, Escape closes it, and focus returns;
    - the user menu opens with Enter and closes with Escape.
  - **CSP:** no `securitypolicyviolation` events and no console errors on any route.
  - **Hosts:** the portal host can't reach `/jobs` (404), and the recruiter host can't reach `/download` (404).
- [ ] CI `web` job (ubuntu):
  - pnpm and Node 24, `pnpm install --frozen-lockfile`;
  - lint, typecheck and unit tests for `@hirevion/ui` and the app;
  - `pnpm exec playwright install --with-deps chromium`, then the e2e suite; the report is uploaded when it fails.
- [ ] Docs:
  - **ADR-0012 (web architecture):** host split by rewrite, the nonce CSP, guards in both the proxy and the layouts, development sessions and their production lock, owned components, next-intl without URL locales, TanStack Table v9;
  - **Runbook:** `pnpm --filter @hirevion/recruitment-platform dev`, the role switcher, the gallery.
- [ ] Commit `docs: add ADR-0012 web app architecture`, then finish the branch: green CI, fast-forward, delete the branch.
