# H0 Catch-up Implementation Plan (lane D, part D1)

**Goal:** what the definition of done promised but SP-04a to SP-06 skipped (PENDING_TASKS.md D1; master plan §14), before CP2:
- policy drafts;
- CI gates: coverage, static analysis, dependency, licence and container scans;
- the PRD traceability check;
- threat models for SP-01 to SP-06;
- a code review of SP-04a to SP-06, with the findings fixed;
- the dashboard's job and candidate KPIs from real data.

## Decisions (defaults; the product owner asked to build without stopping)

- **Policies (`docs/policies/`, PRD §83):**
  - Six drafts: privacy, recording, proctoring, data retention, the deletion process, support and grievance contacts.
  - Each starts with a "draft for legal review" banner, names the hiring organisation as the controller and Hirevion as its processor, and is written to India's DPDP Act 2023 with GDPR-compatible rights.
  - The defaults quoted are the product's own: PRD §84's retention periods, and the consent purposes in SP-09's notice.
  - SP-07b's portal and the desktop link to them; SP-22 makes retention configurable.
- **Coverage:**
  - `pytest-cov` measures `hirevion_core`, excluding the vendor and I/O adapters (the OpenAI-compatible and Deepgram clients, blob storage, SMTP, OCR, the ClamAV scanner, telemetry, the CLI-only migration entry point). Those are covered by contract and live tests instead. The scope is the `[tool.coverage.*]` tables in `pyproject.toml`.
  - CI fails below 85%. Measured at the end of D1: 94.5%.
  - Vitest reports V8 coverage for the web app and fails below the level measured now, rounded down, so it can only rise (lines 72, statements 71, branches 66, functions 66).
- **Static analysis:**
  - Bandit over the Python sources (medium severity and up; the few accepted findings carry `# nosec` with a reason).
  - Semgrep's `p/python`, `p/typescript`, `p/react`, `p/secrets` and `p/owasp-top-ten` rule packs, failing on findings, with an ignore file for test fixtures.
  - Every scanner is a pinned Docker image run by `scripts/gates.sh`, which CI and `scripts/ci-local.sh` both call, so no admin install is needed and the two cannot drift.
- **Dependencies:**
  - osv-scanner over `uv.lock`, `pnpm-lock.yaml` and `Cargo.lock`, failing on known vulnerabilities.
  - `pip-licenses` and `license-checker` fail on strong copyleft (GPL, AGPL, LGPL-3 and SSPL) outside an explicit allow-list, which the licence audit keeps.
- **Container:** the API image is built in CI. Trivy fails on HIGH or CRITICAL vulnerabilities with a fix available; Syft writes an SPDX SBOM uploaded as an artifact.
- **Traceability (`hv trace --check`):**
  - Every Appendix A row names at least one sub-project (`SP-nn`, `§8`, `H0`).
  - Every code reference in backticks (a path, a module, a test file) points at something that exists.
  - A test runs the same check in CI, so a renamed module breaks the build rather than the trail.
- **Dashboard KPIs (PRD §10):**
  - All ten figures come from real data under the seven filters: open jobs, active candidates, screened, shortlisted, the undecided applications in the pipeline, interviews scheduled, live and completed, pending reviews, and proctoring alerts. Each is gated by the permission that reads its data, and a hiring manager's counts cover only their assigned jobs.
  - The semantics (what counts, what each date filter means) are in `hirevion_core.dashboard`; `backend/api/tests/test_dashboard_api.py` checks every figure under every filter against seeded data.

## Outcome

- **CI gates:** all eight run in CI and in `scripts/ci-local.sh`; the runbook's "Quality gates" section says how to run, read and accept each.
  - Findings fixed: 12 dependency vulnerabilities (Next.js to 16.3.8, `source-map-js` pinned to 1.2.2 by an override); a trojan-source finding in `documents/sections.py`; Semgrep's `server_default` SQL-text findings, accepted with a reason beside each.
  - Accepted with a recorded reason: five advisories in Rust crates that only build on Linux (osv-scanner ignores, to 2027-04-19), three licences (`livekit-local-inference`, `@fontsource-variable/inter`, `pypdfium2`).
  - Open for the owner: the LiveKit Model License on `livekit-local-inference` needs counsel's read before a commercial release (STATUS, found in testing).
- **Review of SP-04a to SP-06:** the findings fixed, behaviour first with a failing test each, are listed in the commit messages of the `D1` series; Appendix A rows 10, 13, 18 and 23 name the tests.
- **Left for the lanes that own the code:** the reviewers dialog lists disabled users; the interview page shows no time-zone label; the evaluation re-run button can stick; the candidate page doesn't refresh after an action elsewhere; the assign dialog shows raw window codes. All are A1/A5 code, not resume screening.
