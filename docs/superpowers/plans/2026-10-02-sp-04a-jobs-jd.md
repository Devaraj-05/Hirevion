# SP-04a Jobs and Job Descriptions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jobs with PRD §11's fields, lifecycle and versions, and the job-description pipeline: upload or paste, scan, extract, review and apply. See `docs/superpowers/specs/2026-10-02-sp-04-jobs-documents-design.md`.

**Architecture:**
- **`hirevion_core.jobs`:** jobs, versions, the status machine and the skills taxonomy.
- **`hirevion_core.documents`:** validation, scanning, text extraction and the JD extraction.
- **The flow:** a document change writes an outbox event, and the `documents` consumer (beside the mail consumer in `run_workers`) runs the pipeline with retries and a dead-letter stream.
- **The API** exposes jobs, the job description, apply, versions, retry and skills.
- **The web app** gets the jobs list, a create page, and a job page with details, description review and history.

**Tech Stack:**
- **New:** pdfplumber (MIT), pypdfium2 (Apache-2.0), python-docx (MIT) and charset-normalizer (MIT).
- **Existing:** pgvector; the AI layer (`complete`, `embed`).

## Global Constraints

- **Master plan §13 applies to every task:**
  - UUIDv7 keys and UTC `timestamptz`;
  - row-level security and composite foreign keys;
  - RFC 9457 problems, cursor pagination and `Idempotency-Key` on creates;
  - en-IN and en-US strings;
  - WCAG 2.2 AA;
  - TDD;
  - every route in the authorisation matrix.
- **Untrusted text is data, never instructions.** Prompts wrap the job description in delimiters and say so. Quotes are verified against the source text.
- **Files:**
  - at most 10 MB;
  - the type comes from the magic bytes, not the name;
  - nothing is extracted before the scan passes;
  - quarantined files are never read again.
- **Scope:** team-limited users see only jobs of their teams or their own (`scope_clause`).
- **Audit:** `job.created`, `job.updated`, `job.status_changed`, `job.jd_uploaded` and `job.jd_applied` (PRD §97 "Job created/changed, JD uploaded/changed").
- **Git:** commit as Devaraj-05 only, with no AI attribution.

### Task 1: Schema for jobs, skills, versions and documents

**Interfaces (produces):**
- **`Skill`** (`skills`): shared across organisations. Columns `id`, `name` (citext, unique), `category`. No `organization_id`. `hirevion_app` may only `SELECT`.
- **`SkillAlias`** (`skill_aliases`): `alias` (citext, primary key), `skill_id`.
- **`Job`** (`jobs`), tenant-scoped:
  - columns:
    - `number` (int, unique per organisation), `title`;
    - `department_id`, `team_id` (both nullable, composite foreign keys);
    - `location`, `work_model` (`onsite|hybrid|remote`, nullable);
    - `employment_type` (`full_time|part_time|contract|internship|temporary`);
    - `experience_min`, `experience_max` (numeric(4,1), nullable);
    - `description`;
    - `responsibilities`, `qualifications`, `domain` (text[]);
    - `salary_min`, `salary_max` (numeric, nullable), `salary_currency` (text, nullable);
    - `recruiter_id`, `hiring_manager_id` (users, nullable);
    - `status` (`draft|open|paused|closed|archived`, default `draft`);
    - `version` (int, default 1);
    - `embedding` (vector(1536), nullable);
    - `jd_document_id` (nullable), `created_by`, timestamps;
  - unique (`organization_id`, `id`) and (`organization_id`, `number`).
- **`JobSkill`** (`job_skills`):
  - columns: `organization_id`, `job_id`, `position`, `name`, `skill_id` (nullable), `importance` (`required|preferred|optional`), `min_years` (nullable);
  - primary key (`job_id`, `position`).
- **`JobVersion`** (`job_versions`): `organization_id`, `job_id`, `version`, `snapshot` (jsonb), `reason`, `created_by`, `created_at`; primary key (`job_id`, `version`).
- **`Document`** (`documents`), tenant-scoped:
  - columns:
    - `kind` (`jd|resume`), `job_id` (nullable);
    - `filename`, `content_type`, `size`, `sha256`, `blob_path` (nullable for pasted text);
    - `status` (`uploaded|scanning|extracting|parsing|parsed|quarantined|failed`);
    - `error_code`, `attempts`;
    - `text`, `pages`;
    - `flags` (jsonb), `extraction` (jsonb);
    - `created_by`, timestamps;
  - index on (`job_id`, `created_at`).

### Task 2: The skills taxonomy

**Interfaces:**
- `async def normalise_skills(session, names: Sequence[str]) -> list[NormalisedSkill]` returns `NormalisedSkill(name, skill_id | None)`:
  - it matches on the skill name or an alias, ignoring case and surrounding punctuation;
  - known skills take the canonical name;
  - duplicates collapse, keeping the first;
  - unknown names stay as given.
- `async def search_skills(session, query: str, limit: int = 10) -> list[Skill]` matches by prefix on names and aliases, then by trigram similarity.

### Task 3: Jobs: create, edit, lifecycle, versions and listing

**Interfaces** (`hirevion_core.jobs.jobs`), all taking `(session, actor)`:
- `JobFields`: a frozen dataclass of every editable field, plus `skills: list[JobSkillInput(name, importance, min_years)]`.
- **`create_job(session, actor, fields) -> Job`:**
  - the number is max + 1, retried on conflict;
  - the status is `draft` and the version 1;
  - the version-1 snapshot is written;
  - the audit action is `job.created`.
- **`update_job(session, actor, job_id, changes: JobFields-like partial) -> Job`:**
  - skills are normalised;
  - the version goes up by one and a snapshot is written with the reason `edited`;
  - the audit action is `job.updated`, with the changed fields.
- **`set_status(session, actor, job_id, status) -> Job`:**
  - allowed: draft→open, open→paused, paused→open, open→closed, paused→closed, closed→archived;
  - anything else raises `Conflict("invalid-transition")`;
  - opening needs a title, a description and at least one required skill (`Invalid("job-incomplete")`);
  - writes a version (reason `status`) and the audit action `job.status_changed`.
- **`jobs_statement(scope: ResourceScope, filters: JobFilters) -> Select`:**
  - filters on status, department, recruiter and text;
  - applies `scope_clause(team_column=Job.team_id, owner_column=Job.recruiter_id)`.
- **`get_job(session, job_id) -> JobDetail`:** `job`, `skills`, `department_name`, `recruiter_name`, `hiring_manager_name`, `latest_document`.
- **`list_versions(session, job_id) -> list[JobVersion]`.**
- **Validation (`Invalid` with a field):**
  - title 1–200 characters;
  - experience minimum ≤ maximum, both 0–60;
  - salary minimum ≤ maximum;
  - the department, team, recruiter and hiring manager must be in the organisation (team and department not archived);
  - the recruiter and hiring manager must be active users.

- [ ] **Steps:**
  - failing database tests for each rule, the version count, audit entries and scope filtering (a team-limited user sees team and own jobs only);
  - implement;
  - commit `feat(jobs): create, edit, open and close jobs with versions`.

### Task 4: Documents: validation, scanning and text

**Interfaces** (`hirevion_core.documents`):
- **`files.sniff(data: bytes) -> Literal["pdf","docx","txt","png","jpeg","tiff"] | None`** reads the magic bytes:
  - `%PDF-`;
  - a ZIP header whose entries include `word/document.xml`;
  - PNG, JPEG and TIFF signatures;
  - text that decodes as UTF-8, or that charset-normalizer can decode confidently.
- **`files.check(data, allowed: set[str], max_bytes=10 MiB) -> str`** raises `DocumentRejected(code)` for `too-large`, `empty` or `unsupported-type`.
- **Scanning:**
  - `scan.Scanner` (a Protocol) with `async scan(data) -> ScanResult(clean: bool, signature: str | None)`;
  - `ClamdScanner(host, port, timeout)` uses clamd's `INSTREAM` over TCP;
  - `FakeScanner` flags the EICAR string;
  - `ScanUnavailable` means the scanner couldn't be reached.
- **`text.extract(data, kind) -> ExtractedText(text, pages: int)`:**
  - PDF via pdfplumber, page by page, joined with form feeds;
  - DOCX via python-docx (paragraphs and tables);
  - TXT via charset-normalizer.
  - An encrypted or corrupt file raises `DocumentRejected("unreadable")`.
- **`sections.normalise(text) -> str`:** NFKC, unified line breaks, collapsed spaces, and no zero-width or bidi control characters. The removed characters are counted into `flags["hidden_characters"]`.
- **`sections.detect(text) -> list[Section(name, start, end)]`:** headings on their own line matched against a vocabulary (responsibilities, requirements, qualifications, skills, experience, about, benefits, education, …).

- [ ] **Steps:**
  - failing unit tests:
    - sniff each format from fixtures (tiny PDF and DOCX built in the test with pypdfium2 / python-docx; text);
    - a renamed `.exe` is refused;
    - over-size and empty are refused;
    - the clamd protocol against an asyncio TCP stub answering `stream: OK` and `stream: Eicar-Signature FOUND`;
    - normalisation strips zero-width characters and counts them;
    - sections are found in a sample JD;
  - implement;
  - `uv add pdfplumber pypdfium2 python-docx charset-normalizer` to hirevion-core;
  - commit `feat(documents): validate, scan and extract text`.

### Task 5: The JD extraction, the pipeline and the consumer

**Interfaces:**
- **`jd.JdExtraction`** (pydantic): `title`, `required_skills` and `preferred_skills` (list of `{name, quote}`), `experience_min`, `experience_max`, `responsibilities`, `qualifications` and `domain` (list of `{text, quote}`), `location`, `work_model` (`onsite|hybrid|remote|null`).
- **`async def extract_jd(ai: AiServices, organization_id, text) -> JdResult`:**
  1. one `complete` call (purpose `jd.extract`, prompt version `jd-extract-v1`, schema `JdExtraction`, tier `strong`);
  2. each quote is checked by `quotes.verified(quote, text)` (normalised, whitespace-insensitive substring); unverified items are dropped and counted in `JdResult.dropped`;
  3. skills are normalised in the pipeline's session.
- **`pipeline.process_document(db, storage, scanner, ai, document_id) -> None`:**
  - moves the document through `scanning → extracting → parsing → parsed`, saving the status at each step;
  - on infection it ends in `quarantined`, with `flags.signature`, and the blob moved to `quarantine/` by the storage service;
  - on a rejection it ends in `failed`, with `error_code`;
  - on `AiUnavailable` or `ScanUnavailable` it re-raises, so the consumer retries;
  - for JD documents it saves `extraction` and embeds the normalised text into `jobs.embedding` when the job has no applied profile yet.
- **`consumer.DocumentConsumer(redis, handler)`:** the mail consumer's pattern on the `hv:events:documents` stream, with group `documents`, `xautoclaim` retry, dead letter after 5 attempts (`failed` with `error_code="retries-exhausted"`), and de-duplication by event id.
- **`publish_document(session, document)`** queues the event `document.uploaded`. `retry_document(session, actor, id)` resets a `failed` document to `uploaded` and queues it again (`Conflict` for `quarantined` or `parsed`).
- **`run_workers`** also runs `DocumentConsumer` with real services built from settings. `HV_CLAMAV_HOST` and `HV_CLAMAV_PORT` default to 127.0.0.1:3310. `HV_DOCUMENTS_SCAN=false` skips scanning, only outside production (CI has no ClamAV).

- [ ] **Steps:**
  - failing tests:
    - quote verification;
    - `extract_jd` with a scripted mock LLM drops a made-up quote;
    - the pipeline (database) takes a pasted JD to `parsed` with skills normalised;
    - an EICAR upload is `quarantined` and never extracted;

### Task 6: The API

**Routes** (permissions; creates take `Idempotency-Key`):
- `GET /api/v1/jobs` (`jobs.view`): `status`, `department_id`, `recruiter_id`, `q`, `limit`, `cursor`; ordered by (`updated_at` desc, `id`); scope applied.
- `POST /api/v1/jobs` (`jobs.create`): 201.
- `GET /api/v1/jobs/{job_id}` (`jobs.view`): 404 when outside scope.
- `PATCH /api/v1/jobs/{job_id}` (`jobs.create`).
- `POST /api/v1/jobs/{job_id}/status` (`jobs.create`).
- `GET /api/v1/jobs/{job_id}/versions` (`jobs.view`).
- `POST /api/v1/jobs/{job_id}/jd` (`jobs.create`, `Idempotency-Key`): multipart `file`, or form field `text` (a PRD §90 example endpoint). 202 with the document.
- `GET /api/v1/jobs/{job_id}/jd` (`jobs.view`): the latest document, its status, extraction and dropped count.
- `POST /api/v1/jobs/{job_id}/jd/apply` (`jobs.create`): the reviewed fields. Applying writes them, bumps the version (reason `jd-applied`), re-embeds and audits `job.jd_applied`.
- `POST /api/v1/documents/{document_id}/retry` (`jobs.create` for JD documents).
- `GET /api/v1/skills?q=` (`jobs.view`).
